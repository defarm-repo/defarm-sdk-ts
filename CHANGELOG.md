# Changelog

All notable changes to `@defarm/sdk`. The 0.2.x line is the first with client-side sealing
(0.1.x, in the `tooling` repo, was a thin HTTP client — pre-sealing).

## 0.2.0 — 2026-08-21

First release of the sealing line. Everything below shipped through reviewed PRs (#1–#22)
with cross-language conformance green in CI and the wire format interop-proven against the
Rust reference implementation.

### Breaking changes (pre-publish, no npm release carried the old shapes)

- **`seal()` takes one object** — `seal({ dfid, fieldPath, value, circuitId, ... })` instead of
  positional `seal(dfid, fieldPath, value, opts)`; `open({ dfid, fieldPath })` unchanged. Both now
  validate required fields at the door and throw `InvalidInputError` naming the missing field.
  (PR #7, issue #3)
- **`Keystore` gained a required method** — `getOrCreate(kind, factory)` runs the whole
  get→generate→put cycle under the keystore's lock. Any external `Keystore` implementation (e.g.
  an ERP-side HSM adapter) must implement it; without it, concurrent `ensureKeys()` could
  register two key pairs and keep only one on disk, making fields sealed to the dropped key
  unrecoverable. (PR #10, issue #8)

### Added

- Core N2 sealing (`src/core/`): HPKE X25519/HKDF-SHA256/ChaCha20-Poly1305 envelope, hiding
  commitment, anti-frankenstein AAD, `ed25519_jcs_v1` sealer signature, encryption-key binding
  with mandatory re-verification, vendored RFC 8785 JCS. (PR #1)
- `DefarmClient`: `ensureKeys` / `ingest`(+preview) / `seal` / `open` / `verify`, pluggable
  keystore, typed errors; `grant`/`grantLink`/`revoke` declared but blocked on backend issues.
  (PR #1)
- Cross-language conformance suite: replays vectors generated by the Rust oracle
  (engines#591 / engines PR #606), including a 3-recipient out-of-order envelope, unicode JSON
  content, an API response shaped by the real Rust serializer, and a vector sealed by Rust to a
  key generated by this SDK. Fails closed when no asserting vectors are present. (PRs #1, #7,
  #10, this PR)
- CI: typecheck + full test suite on GitHub Actions (Node 20/22).

### Fixed

- Local authorship re-verification reads `sealer_public_key_b64` (the server's real field name)
  — it silently never ran before. (PR #1 review blocker)
- `ensureKeys` treats a 409 as success only when the registered public key matches the local
  private key (`KeyMismatchError` otherwise). (PR #7, issue #4)
- `FileKeystore`: locked read-modify-write, unique `wx` temp files. (PR #7, issue #6)
