# Conformance vectors (engines#591)

This directory holds `*.json` vector files **generated by the Rust reference implementation**
(`engines .../sealed_field.rs`) — the oracle of the wire format. The TypeScript suite
(`test/conformance.test.ts`) replays them and demands byte-for-byte equality.

The random pieces (DK, nonce, HPKE ephemeral) make a full seal non-deterministic, so vectors
split into:

- **deterministic recomputation** — canonical AAD, hidden commitment, canonical binding and
  signing strings: fixed input → exact expected output;
- **cross-open** — a complete envelope sealed and signed by Rust with a throwaway key pair whose
  private halves are INCLUDED in the vector: TS must open it, get the exact plaintext, and verify
  the sealer signature. (These keys are test fixtures — never real ones.)

**No vectors here = conformance not proven.** The suite passes but warns loudly; a release gate
must require at least one vector file. Generation lands as a small test-tool in the engines repo
(see engines#591).
